# Remotion 类渲染驱动的 21 个坑

> 这一章是“帧表写得漂亮、渲出来不对”的全部原因。
> 每条给三个东西：现象、为什么、契约（写进 JSON 字段或渲染命令，不靠人记）。

## 一、时基：帧号一旦错，全片错

### 坑 01 · fps 硬编码 30
- **现象**：换 25fps 或 60fps 渲染，字幕比嘴慢半拍，转场点整体偏移。
- **为什么**：帧号是 fps 的函数。30fps 下第 300 帧是 10 秒，25fps 下是 12 秒。
- **契约**：`meta.fps` 是必填字段，所有帧号由 `秒 × fps` 派生；`validate.py` 按 `meta.fps` 复算 10 到 20 秒窗口，不认死数字。

### 坑 02 · 秒和帧混着写
- **现象**：稿子里写“大约 3 秒”，渲出来是 2.7 秒或 3.4 秒，CTA 被截。
- **为什么**：自然语言时长无法被脚本核对，也无法被 TTS 对齐。
- **契约**：口播稿只允许 `startFrame` 与 `durationInFrames`；人话时长仅出现在摘要里，且必须标注换算后的帧号。

### 坑 03 · 总帧数手填
- **现象**：`totalCompositionFrames` 与 `Σ scenes − Σ transitions` 差几十帧，结尾黑屏或截断。
- **为什么**：`TransitionSeries` 的转场是**重叠消耗**，不是额外插入。
- **契约**：`total = Σ durationInFrames − Σ transition.durationInFrames`，`validate.py` 的 A2 项逐帧复算，不等就报错。

### 坑 04 · startFrame 手填
- **现象**：转场处出现 8 帧空洞（前一场已结束、后一场未开始）或两场同时在场。
- **为什么**：转场让相邻两场重叠，下一场起帧不是上一场结束帧。
- **契约**：`startFrame[i] = startFrame[i-1] + duration[i-1] − transition(after i-1)`；`validate.py` 的 A3 项按此递推比对，差一帧都报。

### 坑 05 · 转场时长超过相邻场景的一半
- **现象**：`TransitionSeries` 报错，或短场景被转场吃掉，15 字微型钩子整场消失。
- **为什么**：官方要求转场时长不超过相邻 sequence 的一半，否则两场无法同时呈现。
- **契约**：`transition ≤ min(前一场, 后一场) / 2`，A1 项卡死；微型钩子场景只有 30 到 45 帧时，转场最多 15 帧。

### 坑 06 · 首场之前或末场之后挂转场
- **现象**：渲染直接抛错，或首帧变成透明。
- **为什么**：没有前一场可叠。原稿“两个转场不得相邻”其实指的就是这个边界。
- **契约**：`after_scene` 不得指向末场，不得重复指向同一场；A1 项校验。

### 坑 07 · 用 springTiming 却按帧数算时长
- **现象**：声明 12 帧的转场实际跑了 28 帧，节奏全部后移。
- **为什么**：`springTiming` 的落位时长由阻尼与刚度决定，不等于声明的帧数。
- **契约**：转场统一用 `linearTiming({durationInFrames})`；需要弹性就放在场景内 `spring()`，并用 `durationInFrames` 显式封顶。

## 二、音频：先有声，才有帧

### 坑 08 · 先画帧后配音
- **现象**：TTS 出来 41 秒，画布 36.6 秒，最后一句被切，或末尾空 4 秒冷场。
- **为什么**：音频是事实，画面是设计。让事实迁就设计必然错位。
- **契约**：先出 TTS 拿真实时长，再用 `calculateMetadata` 或 `getAudioDurationInSeconds` 反算 `durationInFrames`；`validate.py` 的 R5 项按字速预估与目标时长比对，偏差超 15% 报警。

### 坑 09 · 给 TTS 的文本里混进 markdown
- **现象**：配音读出“星号星号”，或在不该停的地方停半秒。
- **为什么**：`**但问题是**` 是给人看的强调标记，TTS 当字符处理。
- **契约**：拆成两个字段。`voiceover_text` 纯文本给 TTS，`emphasis_words` 数组给字幕高亮。R2 项扫 `voiceover_text` 里的 markdown 与全角符号。

### 坑 10 · 中文按字符切片的打字机
- **现象**：emoji 或生僻字渲染成方块，或某帧突然少一个字。
- **为什么**：JS `slice` 按 UTF-16 码元切，代理对会被劈开。
- **契约**：用 `Array.from(text)` 或 `Intl.Segmenter('zh', {granularity:'grapheme'})` 切；打字机场景全片不超过 2 个（D2 项）。

### 坑 11 · 没有语速预算
- **现象**：稿子读完还剩 6 秒，画面空转；或字幕比画面快，观众跟不上。
- **为什么**：中文口播常态 5 到 6.5 字每秒，快节奏可到 7.5，没人写过这条约束。
- **契约**：每场 `汉字数 ÷ (durationInFrames ÷ fps)` 必须落在 3.2 到 8.0；R3 项逐场算，超区间报具体场景号。

## 三、确定性：同一份稿，两台机器渲出两条片子

### 坑 12 · 渲染里用 random 或 Date
- **现象**：本地看着正常，云端渲出来元素位置全变，二次渲染不可复现。
- **为什么**：Remotion 靠帧号驱动，取系统时间与随机数会破坏确定性。
- **契约**：禁止 `Math.random()`、`Date.now()`、`performance.now()`；需要抖动就用 `random(seed)` 传固定种子。

### 坑 13 · 用 CSS transition 或 animation
- **现象**：预览能动，渲染出来定格在首帧，或整段消失。
- **为什么**：无头浏览器逐帧截图，CSS 动画不随帧号推进。
- **契约**：全部用 `useCurrentFrame()` + `interpolate()` + `spring()`；R 组扫源码时见到 `animation:` 键一律报。

### 坑 14 · 字体没加载就渲染
- **现象**：首帧全豆腐块，或前 10 帧字重突变。
- **为什么**：无头 Chromium 不带中文字体，字体是异步加载的。
- **契约**：`loadFont()` 包在 `delayRender()` / `continueRender()` 里，或把字体文件放 `public/` 用 `staticFile()` 引用；首帧强制等字体就绪。

### 坑 15 · 远程图片与视频没预加载
- **现象**：并发渲染时偶发缺图，重渲一次又好了。
- **为什么**：截图不等网络。
- **契约**：图片用 `<Img>`，视频用 `<OffthreadVideo>`（不要用 `<Video>`，并发下会丢帧），都配合 `delayRender()`。

## 四、画面与平台：渲得出来，发不出去

### 坑 16 · 第 0 帧是入场动画的起点
- **现象**：视频起播是半透明空画面，抖音抽这一帧当封面，点击率直接掉。
- **为什么**：`slide-from-bottom` 在第 0 帧的位移量是满值，元素还在画面外。
- **契约**：`scenes[0].first_frame_visible` 必须为 `true`，且 `enterFrames ≤ 18`；A4 项卡死。封面另有 `poster` 字段可单独出图。

### 坑 17 · 字幕落进抖音 UI 遮挡区
- **现象**：底部文案、右侧点赞栏压住字幕，关键句读不到。
- **为什么**：1080×1920 的画面不等于 1080×1920 的可读区。
- **契约**：`meta.safe_area` 上 200、下 400、左 60、右 200；`subtitle_lines` 每行不超过 16 字、最多 2 行；R4 项按此校验。

### 坑 18 · 输出编码参数缺失
- **现象**：上传后二次转码发糊，或音画错位 200ms。
- **为什么**：默认 `yuv444p` 抖音不认，会强制转码；帧率非整数也会被重采样。
- **契约**：渲染基线固定为
  ```bash
  npx remotion render <id> out.mp4 --codec=h264 --crf=18 \
    --pixel-format=yuv420p --concurrency=4 --audio-codec=aac
  ```
  成片峰值电平 -1dB，采样率 48kHz。

### 坑 19 · 一份 scenes 复用到另一个尺寸
- **现象**：改成 3:4 或 1:1，字号与留白全塌，字幕溢出。
- **为什么**：坐标与字号是按 1080×1920 写死的，不是按比例。
- **契约**：尺寸与安全区只从 `meta` 读，组件内禁止硬编码像素；小红书分支按 3:4 重出布局，不直接复用抖音帧表。

### 坑 20 · 渲染预算没算
- **现象**：本机渲一条 40 秒竖屏要 4 到 8 分钟，`concurrency` 开满直接内存爆。
- **为什么**：1080×1920 每帧解码内存约为 720p 的两倍。
- **契约**：`concurrency` 取 4，机器 16GB 内存上限 6；一次渲两条时串行跑，不并发。

### 坑 21 · 把“情绪峰值”当视觉峰值
- **现象**：全程满屏动效，观众眼睛累，第 15 秒照样划走。
- **为什么**：留人靠文案，动效只负责托住情绪，不负责制造情绪。
- **契约**：`motion_budget` 0 到 3；`direction = down` 的场景 ≤ 1，微型钩子场景 ≤ 相邻功能场景的一半（B7/B8 项）。

## 附 · 渲染前 30 秒自检清单

1. `meta.fps` 与 `remotion.config` 里的一致吗？
2. 音频时长反算过 `durationInFrames` 吗？
3. 第 0 帧截图看过了吗，有主体吗？
4. 字幕在安全区内吗？
5. 字体在 `public/` 且在 `delayRender` 里等了吗？
6. 源码里还有 `Math.random` 或 CSS `animation` 吗？
7. 输出参数是不是 `h264 + yuv420p + aac`？
